# Vertex(실제 모델) 실행 규칙

Vertex를 부르는 세션(테스트·실행 세션)은 **매번 실행 전에 이 문서를 다시 읽어요.**
부탁이 아니라 이 작업의 규칙이에요. 하나도 빠짐없이 지켜요.

## 왜 이렇게 엄격한가

- Vertex 호출 한 번이 곧 소망의 돈이에요. "확인하려고" 한 번 더 돌릴 때마다 돈이 나가요.
- 지운 로그는 비교 자료가 사라진 거예요. 그걸 다시 만들려고 또 돌리게 돼서 돈이 두 번 나가요.
- 비교 실행은 같은 조건으로 한 번씩 돌려야 비교가 돼요.
  - 결과가 마음에 안 든다고 다시 돌리면, 그건 비교가 아니라 좋은 결과를 고르는 거예요. 그 숫자는 쓸 수 없어요.
- 실패도 결과예요. 실패하면 실패한 그대로 적어서 보고해요. 다시 돌려서 덮지 않아요.
- 사과는 필요 없어요. 사과하고 같은 일을 또 하면 그 사과는 의미가 없어요. 규칙을 지키는 걸로 보여 줘요.

## 규칙

1. **돌리기 전에 먼저 보고해요.**
   - 몇 번 부를지: 단계별 호출 수와 합계
   - 어느 커밋인지
   - 어느 폴더에 저장할지
   - 소망이 "ㄱㄱ"라고 하기 전엔 Vertex를 한 번도 부르지 않아요.
2. **호출 상한을 코드로 걸어요.**
   - 하네스에 최대 호출 수(보고한 합계)를 넣어요. 넘으면 호출하기 **전에** 멈추고 에러를 내요.
   - "조심할게"가 아니라 코드로 막아요.
3. **실패하면 멈춰요.**
   - 호출이 실패하거나 답이 이상해도 다시 부르지 않아요.
   - 그 상태 그대로 저장하고 보고해요.
4. **지우지 않아요.**
   - 파일·로그·폴더는 하나도 지우거나 덮어쓰지 않아요.
   - 새 실행은 새 폴더(`log_runN`)에만 써요.
   - 정리가 필요하면 지울 목록을 보여 주고 허락받아요.
5. **키 값은 어떤 형태로도 출력하지 않아요.** 키를 붙여 달라고 하지도 않아요.
6. **보고는 한 번에 해요.**
   - 호출 수(계획 vs 실제), 토큰, 시간, 결과를 한 번에 정리해요.
   - 계획보다 한 번이라도 더 불렀으면 맨 위에 그 사실부터 써요.

## 실행 전 체크리스트

- [ ] 이 문서를 다시 읽었다
- [ ] 호출 수·커밋·저장 폴더를 보고했고, 소망의 "ㄱㄱ"를 받았다
- [ ] 하네스의 호출 상한을 보고한 숫자로 걸었다
- [ ] 저장 폴더가 새 폴더이고, 지우거나 덮어쓰는 코드가 없다
- [ ] 키를 출력하는 줄이 없다
