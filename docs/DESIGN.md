# 디자인 인수인계 (휴대폰 · 확장 패널)

이 문서는 NarrativeArchive의 **디자인 작업**(캐릭터 휴대폰과 확장 패널 · 팝업)을 넘겨받는 세션을 위한 것이에요. 처음부터 끝까지 한 번 읽고 시작해 주세요.

| 장 | 무엇 |
|---|---|
| 1. 가장 먼저 | 소망과 말하는 법 |
| 2. 작업 단계 | 시안 → 코드 → 실제 폰 확인 → 커밋 · 메인 |
| 3. 가장 중요한 것 | 소망이 정해 준 기준, 디자인 철칙 |
| 4. 놓치지 말 것 | 테마 충돌, 함정, 반영 세션 경계 |
| 5. 이렇게 하는 이유 | 소망이 싫어하는 것 · 좋아한 것 |
| 6. 화면별 참고 | 공통 토큰, 은행 · 지갑 · 날씨 · 그 밖의 앱 |
| 7. 확장 패널 · 팝업 | 휴대폰 바깥 |
| 8. 남은 일 | |

---

## 1. 가장 먼저 (시작 전에)

### 소망과 말하는 법

- 사용자 이름은 소망이에요. 소망은 짧은 한국어 반말체로 말해요(ㅋㅋ, ㄱㄱ 같은 말을 써요). 답은 짧고 쉬운 한국어로, 존댓말(~요)로 해요.
- 답을 감정 이야기로 시작하지 않아요("놀라셨겠지만" 같은 말 금지).
- 묻지 않은 조언은 하지 않아요.
- **질문에는 답만 해요. 코드는 건드리지 않아요.** "이거 어케 돼?", "흠 어카지"는 질문이에요. 질문에 코드를 고쳤다가 크게 화낸 적이 있어요.
- "넹", "굿", "웅", "ㄱㄱ", "ㅇㅋ"는 진행해도 된다는 뜻이에요. 메인에 올릴 때는 꼭 이 말을 받고 올려요.
- 설명이 길거나 어려우면 "먼소리야"가 와요. 쉬운 말로 다시 짧게 해요.
- 지시가 두 가지로 읽히면 짧게 확인해요. 예: "저 보라 카드 지워"는 색이 아니라 그 **카드 디자인(사선 줄무늬)**을 빼라는 말이었어요. 세 번을 헛짚었어요.

## 2. 작업 단계

### 순서

1. **시안부터.** 새 화면이나 큰 변경은 HTML 시안을 3~4개 그려 Playwright로 찍어 보여주고 고르게 해요. 시안을 더 달라는 요청도 자주 와요. 시안이 서로 확실히 달라야 해요.
2. 고른 걸 코드로 옮겨요.
3. **실제 폰에서 찍어서** 보여줘요(2장 3단계). 시안 그림만 보여주고 끝내지 않아요.
4. 작업 브랜치에 커밋하고 올려요. 메인은 허락받고 올려요(2장 4단계).

### 1단계: 시안 그리기

- HTML 한 파일에 폰 프레임(390 × 844, 둥근 44px, 검정 테두리)을 나란히 그리고, 위에 "A. …" 라벨을 달아요. Playwright로 `fullPage` 찍어서 보내요.
- 시안 아이콘도 SVG 선 아이콘으로 그려요.
- 버튼 위쪽 빛, 그림자 같은 지금 앱의 질감을 시안에도 넣어요. 빠지면 예전 CSS보다 덜 고급스러워 보여요.
- 실제 데이터 모양(독일어 상점 이름 + 한국어)으로 채우면 판단하기 쉬워요.

### 2단계: 코드로 옮기기

#### 화면이 그려지는 방식

- 화면은 전부 **HTML 문자열을 돌려주는 함수**예요. 프레임워크는 없어요.
- 앱 화면은 390 × 844 보드 크기로 그리고, 실제 창에 맞춰 줄여요.
- 루트 클래스는 `.na_ph_scr.ax`이고, 앱 안에서는 `.ax`가 기준이에요.
- 눌러서 화면을 옮기는 건 `data-go="경로"`(+ `data-i="값"`)예요. `src/phone.js`의 `$root.on('click', '.na_ph_frame [data-go]', …)`가 받아서 `view = "경로:값"`으로 바꾸고 다시 그려요. `<button>`이 아니어도 `data-go`만 있으면 눌려요(예: 명세서 표의 `<tr>`).

#### 주요 파일

| 파일 | 내용 |
|---|---|
| `src/phone.js` | 화면 고르기(`screen()`), 경로표, 클릭 처리, 스크롤 유지, 은행 환율 칸 처리 |
| `src/phoneapps.js` | 공용 도우미와 아이콘 `AX`, 앱별 색 `AXB` / `AXB_C`, 메시지 · 전화 · 사진 등 1쪽 앱들 |
| `src/phonehome.js` | 잠금 · 홈 1쪽 · 2쪽, 홈 아이콘(`CG_I` 모양, `CG_GEL` 색), 위젯 |
| `src/phonemoney.js` | 은행 · 고정 지출 · 알림 · 송금 · 명세서 · 확인증 · 더보기, 지갑(카드 · 멤버십 · 패스), 쇼핑, 음성 메모 |
| `src/phonelifeapps.js` | 시계 · 건강 · 파일 · 날씨 · 배달 · 홈 날씨 위젯 |
| `src/phonefood.js` | 음식 그림(바탕 159개, 토핑, 곁들임). 낱말로 그림 고르기(`GUESS`, `WORD`, `wordsPic`, `dishPic`) |
| `src/phoneprod.js` | 쇼핑 상품 실루엣 50종. 낱말로 종류 · 색 고르기(`prodKind`, `prodSvg`) |
| `src/phonedata.js` | 폰 데이터 모양, 채우기 프롬프트, `storyNow` |
| `src/phonelife.js` / `phonesync*.js` | 채우기 · 반영(데이터 쪽). **4장 데이터 쪽 경계 참고, 건드리지 않아요** |
| `style.css` | 전부 한 파일(약 7000줄). 앱마다 주석 머리(`/* 은행 › … */`)로 묶여 있어요 |

#### 공용 도우미 (`src/phoneapps.js`)

- `ax(k, size=22, color='currentColor', strokeWidth=2, fill='none')`: `AX[k]` 경로로 선 아이콘 SVG를 만들어요.
- 새 아이콘은 쓰는 파일 위쪽에 `Object.assign(AX, { 이름: 'path d' })`로 더해요. 24×24 기준 선 아이콘이에요.
- **이름이 겹치면 덮어써요.** 먼저 `grep -n "이름:" src/*.js`로 확인해요.
- `axBar(p, now, color)`: 상태줄이에요.
- `axTop(left, right)`: 위쪽 줄이에요.
- `axCb(go)`: 둥근 뒤로 버튼이에요.
- `axH1(title, sub)`: 큰 제목이에요.
- `axInd(color)`: 아래 홈 막대예요.
- `axDay(p, now, 'MM-DD')`: "오늘" 또는 날짜예요.
- `axTint(name)`: 이름마다 고정된 아바타 색이에요.
- `axLetter(name, size)`: 글자 아바타예요.
- `axKp(p)`: 한국어 알약이에요.
- `busyHtml`: 도는 아이콘이에요.

#### 새 화면을 더할 때 체크리스트

1. 화면 함수는 `export function xxxScreen(p, now, i)`예요. 앞뒤를 `axBar` … `axInd()`로 감싸요. 은행류는 `.ax_bk` 구조를 따라요(6장).
2. `src/phone.js`
   - import에 더해요.
   - `screen()`의 `v === '경로' ? …` 줄, 또는 `life` 맵에 더해요.
   - `data-i`를 **늘** 받는 경로면 클릭 처리의 `view = [ … ].includes(go)` 첫 목록에 더해요. **있을 때만** 받는 경로면 두 번째 목록(`['cal', …, 'wallet']`)에 더해요.
   - 같은 화면 안에서 고르기만 바뀌는 경로(고정 지출 · 송금 · 명세서 · 지갑)는 `const stay = [...]`에 더해요. 그래야 스크롤 위치가 남아요.
3. `src/phoneapps.js`의 `AXB`에 `경로: '색이름'`을 더해요. 앱 강조색이 `--axd` · `--axc`로 들어와요.
4. CSS를 `style.css`의 그 앱 묶음에 더해요(3장 디자인 철칙, 4장 테마 충돌 규칙대로).
5. 테스트 → 실제 폰 확인 → 버전 → 커밋(2장 3~4단계).

### 3단계: 실제 폰에서 확인


#### 준비 (한 번)

1. SillyTavern을 받아요(1.19.0에서 확인).
   ```bash
   git clone https://github.com/SillyTavern/SillyTavern ~/sillytavern && cd ~/sillytavern && npm install
   node server.js   # :8000 (config.yaml이 처음 생겨요. whitelistMode 기본값으로 127.0.0.1 접속 가능)
   ```
   새로 깐 SillyTavern은 처음 열 때 **환영 창(페르소나 이름)**이 떠서 캐릭터 목록이 안 불려요(`probe.cjs`가 `characters?.length > 0`에서 멈춰요). 한 번 저장을 눌러 넘겨요.
   ```js
   await p.goto('http://127.0.0.1:8000/'); await p.waitForTimeout(8000); await p.click('dialog .popup-button-ok');  // settings.json의 firstRun이 false가 돼요
   ```
   기본 연결이 AI Horde인데 클라우드 세션에서는 Horde에 접속이 안 돼요. `data/default-user/settings.json`의 `"main_api": "koboldhorde"`를 `"openai"`로 바꿔 둬요. 로그의 `aihorde.net` 오류와 확장 업데이트 500(`Directory is not a Git repository`)은 무시해도 돼요.
2. 확장을 넣어요(바꿀 때마다 다시 복사).
   ```bash
   mkdir -p ~/sillytavern/data/default-user/extensions/NarrativeArchive
   cp -r manifest.json index.js src style.css css assets ~/sillytavern/data/default-user/extensions/NarrativeArchive/
   ```
   `style.css`는 `css/` 파일들을 `@import`로 불러요. `css`를 빼먹으면 스타일이 하나도 안 먹어요(콘솔에 `Refused to apply style … MIME type ('text/plain')`).
   `src` · `style.css` · `css`만 바뀌었으면 그 셋만 복사해요. 브라우저를 새로 열면 반영돼요.
3. 테스트 채팅을 넣어요. 기본 캐릭터 Seraphina가 0번이어야 해요.
   ```bash
   mkdir -p ~/sillytavern/data/default-user/chats/default_Seraphina
   cp tools/dev/na_test.jsonl ~/sillytavern/data/default-user/chats/default_Seraphina/
   ```
4. 가짜 모델을 켜요: `node tools/dev/fakeph.mjs`(:5555). 폰 만들기 · 채우기 · 반영에 정해진 답을 줘요. 마지막 요청은 `$TMPDIR/na_fakeph_last_req.json`에 남아요(프롬프트 확인용).
5. Playwright: 클라우드 세션에는 Chromium이 미리 깔려 있어요. `playwright install`은 하지 않아요.

#### 찍기

```bash
node tools/dev/probe.cjs light   # 또는 dark → ./shots/home_light.png, home2, bank, wallet
```
모듈로 쓰면 원하는 화면을 찍을 수 있어요.
```js
const { open, SAMPLE_MONEY } = require('./tools/dev/probe.cjs');
const s = await open('light');              // 채팅 열기 → 폰 만들기(가짜 모델) → 잠금 해제
await s.run(SAMPLE_MONEY);                  // 은행 · 지갑 예시 데이터
await s.run(async ({ ph }) => { ph.life.weather.here.cond = 'fog'; });  // 데이터 직접 바꾸기
await s.to('bank'); await s.shot('bank');   // data-go 그대로
await s.p.click('.ax_bkacts [data-go=stmt]');  // 진짜로 눌러 보기
await s.scroll(); await s.shot('bank_bottom');
console.log(await s.overflow(), s.errors());   // 옆으로 삐져나온 것, 페이지 오류
await s.close();
```
- 여러 장을 한 장으로 붙일 때: PIL(`Image.new` + `paste`)이나 `ffmpeg … -filter_complex hstack`
- 움직이는 화면(날씨 등)은 `open(theme, { video: 'dir' })`로 녹화해요. 장면마다 폰 프레임 안에 분홍 라벨 div를 붙이고, 그 라벨이 처음 나온 프레임부터 `ffmpeg -ss`로 잘라요. 녹화 시간과 실제 시간이 어긋나서 시간 계산으로 자르면 틀려요.
- 보여줄 땐 실제 폰 화면을 보내요. 확인 못 한 것은 확인 못 했다고 말해요.

### 4단계: 브랜치 · 버전 · 커밋

- 작업은 세션에 정해진 브랜치에서 해요. **메인은 소망이 OK한 뒤에만** 올려요.
  ```bash
  git fetch origin main && git rev-list --count HEAD..origin/main   # 0이어야 그대로 올릴 수 있어요
  git push origin HEAD:main
  ```
  0이 아니면 메인을 먼저 받아서 합쳐요. 반영 쪽 세션도 메인에 올려요.
- 버전은 두 곳을 같이 올려요: `manifest.json`의 `"version"`과 `src/core.js`의 `export const VERSION`. 새 기능이면 가운데, 다듬기면 끝자리를 올려요.
- 커밋 메시지는 영어 한 줄 요약(화면에서 무엇이 어떻게 보이게 됐는지)이에요. 끝에 세션이 주는 Co-Authored-By 줄을 붙여요.
- 강제 푸시는 막혀 있어요.
- 큰 기능은 `README.md`의 해당 절(`## 캐릭터 휴대폰 · 투자`)에도 한두 줄 적어요.

## 3. 가장 중요한 것

### 소망이 정해 준 기준 (그대로 지켜요)

- 고르신 건 건드리지 않고, 안 고른 것만 다시 그려요.
- 동그라미 안 친 건 넣지 않아요.
- 기존 디자인의 "퀄리티를 맞추라"는 말은 "기법을 베끼라"는 뜻이 아니에요.
- 정해진 배치 · 디자인은 혼자 바꾸지 않아요.
- **보내기 전에 멈춰서 봐요.** 빨리 내놓는 것보다 맞는 게 먼저예요. 실제 폰에서 찍은 걸 원래 것과 직접 비교하고(글자 깨짐 · 색 차이 · 안 고른 게 들어갔는지), 이상하면 먼저 고친 뒤에 보내요. 퇴짜가 이어지면 짐작으로 다시 그리지 말고, 고르신 것의 공통점부터 정리해요. 말이 애매하면(이름 · "퀄리티만큼" 같은 말) 내 식으로 바꾸지 말고 묻고 시작해요.
- **문서를 고칠 때:** 원래 파일을 고치는 방식으로 하고, 새로 쓰지 않아요. 고친 뒤 diff를 직접 훑어 빠진 정보가 없는지 보고 올리고, 무엇을 뺐는지 목록으로 말해요.
- **줄 원칙:** 줄은 넘기지 않고, 길면 "…"으로 줄여요. 단, 원래 그렇게 생긴 화면은 바꾸지 않아요.
- **광학 정렬(optical alignment):** 아이콘과 글자가 눈으로 봐서 가운데에 맞아야 해요. 숫자상으로만 가운데면 안 돼요.
- **은은한 입체감:** 흰 카드에는 그림자를 넣고, 둥근 버튼 위쪽에는 살짝 빛(inner highlight)을 넣어요. 평평한 흰 덩어리는 안 돼요.
- **페더링(feathered edge):** 무늬는 한쪽(보통 오른쪽)에 깔리고, 글자 쪽으로 길고 부드럽게 사라져요. 딱 끊긴 경계는 안 돼요.
- **피해야 할 것:** 클립아트 · PPT 도형(네모 · 원 · 삼각형 그대로) · 듬성듬성한 선 · 장식용 그라데이션 띠 · 엠보싱 마크 · 징그러운 반복(작은 칸 안에 또 칸이 있는 것) · 키보드처럼 보이는 격자
- **일러스트가 아니라 재질 · 표면(texture / surface, not illustration):** 퀼팅, 대리석, 다마스크, 뜨개, 필름 그레인, 홀로그램처럼 그 장소의 물성이에요. 마이크 · 바퀴 · 방패 같은 오브젝트나 무대 · 호텔 같은 장면은 안 돼요.

### 디자인 철칙

지금 폰의 분위기는 수십 번 고치면서 맞춘 거예요. 아래는 그 과정에서 굳은 원칙이에요. 새 화면도 이 원칙을 따라야 같은 폰처럼 보여요.

#### 3-1. 진짜 폰처럼, 하지만 장난감 같지 않게

- **실제 앱의 문법을 빌려요.** 사람들이 눈으로 아는 실제 앱의 배치 · 위계 · 몸짓을 따라요. 날씨는 애플 날씨, 지갑은 애플 지갑 덱, 배달은 배달의민족 / Uber Eats, 은행은 국내 은행 앱의 남색 머리, 쇼핑은 깔끔한 커머스 목록이에요. 상표 · 로고를 베끼는 게 아니라 "이 화면은 이렇게 생겼다"는 익숙함을 가져와요.
- **보드 크기로 그려요.** 모든 앱은 390 × 844 보드 기준 px로 그리고 화면에 맞춰 줄여요. 글자 크기 · 여백도 진짜 아이폰 크기 감각으로 정해요. 본문 14.5~15px, 보조 12~12.5px, 아주 작은 라벨 10.5~11px, 큰 숫자 34~38px예요.
- **이야기 속 물건처럼 보이게.** 데이터가 그 인물의 삶이라 화면도 그 사람 폰이어야 해요. 독일에 사는 인물이면 독일 가게 이름, 유로, IBAN, 독일 우편 회사가 나와요. 한국어는 보조 줄(ko)로만 붙어요. 나라마다 모양이 다른 건(계좌번호, 택배사, 날짜 · 숫자 모양) 나라에 맞춰요.
- **지어낸 세부도 늘 같아야 해요.** 고객 번호, 승인 번호, 계좌번호, 사진 장면, 카드 무늬처럼 코드가 지어내는 건 이름 · id 해시로 정해서 열 때마다 같게 나와요. 무작위 값은 쓰지 않아요.

#### 3-2. 색

- **먼지 낀 파스텔.** 앱 바탕색과 아이콘 타일은 채도를 낮춘 부드러운 색이에요. 원색 주황 · 초록 · 보라는 쓰지 않아요. 건강은 피치 · 민트 · 라벤더블루, 홈 아이콘은 `CG_GEL`의 두 톤 젤(투명도 0.85)이에요.
- **한 앱 한 색.** 앱마다 강조색 하나(`AXB_C`의 진한색 `--axd` + 옅은색 `--axc`)를 정하고 그 앱 안에서는 그 색만 강조에 써요. 홈에서 옆 아이콘끼리 비슷한 색이 붙으면 안 되고, 하나만 채도가 튀어도 안 돼요. 노랑은 금방 똥색이 돼서 크림 쪽으로 눌러요.
- **아이콘 타일은 같은 색의 옅은 바탕 + 진한 선.** 예: 바탕 `#e2e9f5`에 선 `#2c4a80`, 바탕 `#dcefdf`에 선 `#3f7d50`. 흰 글자를 꽉 찬 원색 위에 얹는 타일은 피해요(글자 아바타 `axTint`는 예외).
- **돈 색은 정해져 있어요.** 들어온 돈 초록 `#3f7d50`, 나간 돈 · 급한 D-day 주황빨강 `#b8573a`, 대기 · 승인 대기 노랑 `#8a6a1f` / `#f3e8c9`, 정보 · 링크 남색 계열이에요.
- **이미 정한 색은 그대로 둬요.** 은행 남색 `#1d3461`, 카드 등급 색(GOLD 금, PLATINUM 은, BLACK · PRIVATE 검정 + 금선)은 앱의 얼굴이에요. 문제가 생기면 색이 아니라 배치로 풀어요.
- **보라는 조심해요**(5장). 보라색 은행 카드는 빠졌어요.

#### 3-3. 깊이 (그림자와 빛)

- **떠 있는 건 다 그림자가 있어요.** 그림자가 없으면 흰 덩어리처럼 보여요. 그림자는 늘 두 겹이에요. 바로 밑의 아주 얕은 선(`0 1px 2px` 4~5%) + 넓고 옅은 번짐(`0 8~14px 24~30px` 5~18%)이에요. 물건이 클수록, 위에 있을수록 진하게 해요(목록 카드 < 종이 < 실물 카드).
- **어두운 면 위의 버튼에는 위쪽 빛.** 남색 · 검정 위 둥근 버튼과 카드에는 `inset 0 1px 0 rgba(255,255,255,.14~.2)`로 윗변에 빛을 얹어요. 고급스러움은 대부분 이 한 줄에서 나와요.
- **테두리 대신 면과 그림자.** 굵은 테두리는 거의 안 써요. 나눔은 `#eef0f3` 같은 아주 옅은 머리카락 선이고, 목록에서는 아이콘 오른쪽부터 시작해요(`.ax_rw + .ax_rw::before`).
- **겹치는 물건은 실제처럼 겹쳐요.** 지갑 덱은 카드가 다음 카드 밑으로 이어져서 둥근 모서리 사이로 뒤 카드가 비쳐요. 자르면 안 예뻐요. 위 카드는 아래 카드 쪽으로 옅은 그림자(`0 -3px 12px`)를 떨궈요.

#### 3-4. 그림 (일러스트)

- **플랫하게.** 음식 · 하늘 · 사진 썸네일 · 문서 첫 장 · 상품은 전부 평평한 면을 겹쳐 그린 SVG예요. 그라데이션과 사실적인 질감은 쓰지 않아요. 예외는 프리미엄 카드의 금속 광택(플래티넘 · 골드 · 브러시드 블랙)뿐이에요.
- **몇 개의 면으로 알아보게.** 하늘은 하늘색 + 띠 + 언덕 세 겹 + 구름이에요. 음식은 접시 + 바탕 + 토핑 층이에요. 작은 디테일을 더하다 벌레처럼 보인 적이 있어요(육회 마블링). 작은 점 · 결은 아끼고, 알아보는 데 필요한 모양(꼬불꼬불한 육회, 노른자, 베이글 구멍)만 또렷하게 해요.
- **바탕과 구분되게.** 그릇 · 유리잔이 배경색에 묻히면 안 돼요(와인잔이 그랬어요). 그림 바탕색은 그림 속 주인공과 대비가 나게 골라요.
- **글자를 가리지 않게.** 위젯 · 카드 위 그림은 가운데나 한쪽으로 몰고, 이름 · 온도 · 숫자 자리는 비워 둬요(홈 날씨 위젯).
- **같은 모양을 줄줄이 반복하지 않아요.** 똑같은 굵기의 안개 줄 네 개가 징그러워 보였어요. 반복이 필요하면 굵기 · 진하기 · 길이를 바꿔 원근감을 줘요(위로 갈수록 얇고 흐리게).

#### 3-5. 글자와 숫자

- 본문은 시스템 글꼴, 숫자는 `'Inter Tight'`(`.cg_num`)예요. 큰 숫자는 굵기 600에 글자 사이를 살짝 좁혀요(`letter-spacing: -0.01~-0.02em`).
- 큰 숫자 하나, 그 위에 작은 회색 라벨 하나, 아래에 작은 보조 줄 하나. 머리 영역은 늘 이 세 줄 구조예요(잔액, 매달 나가는 돈, 온도).
- 라벨은 짧은 한국어예요("사용 가능", "이번 달 사용", "곧 나가요"). 설명문을 화면에 길게 쓰지 않아요.
- 실물을 흉내 내는 곳은 실물 글자를 써요. 카드의 CARD HOLDER / VALID THRU, 패스의 영문 대문자 회사명(자간 넓게), 명세서 · 확인증의 문서 번호가 그래요.

#### 3-6. 모양과 여백

- 둥글기: 큰 카드 · 시트 22px, 타일 · 실물 카드 16~20px, 아이콘 타일 11~13px, 칩 · 배지 999px이에요. 한 화면에 둥글기 단계가 너무 많지 않게 해요.
- 좌우 여백은 14~16px, 목록 줄은 위아래 12px, 카드 사이는 12~14px예요.
- **확장 창은 위아래 여백이 같아야 해요(둘 다 16px).** 몇 번이나 말한 규칙이에요. 창 아래 버튼 줄을 직접 만들면(ST 기본 버튼을 숨기고 `닫기 | N개 바꾸기` 같은 줄을 넣으면) 기본 버튼 줄의 아래 10px이 사라지니 꼭 다시 넣어요. 결과 · 진행 중 화면도 같아야 해서, 고친 뒤에는 처음 화면과 결과 화면을 둘 다 재 봐요.
- 섹션은 "작은 회색 제목 → 흰 카드" 묶음으로 나눠요. 카드 안에 또 카드를 넣지 않아요.

#### 3-7. 정보와 상호작용

- **보이는 건 다 눌려요.** 버튼처럼 생긴 건 무언가를 열어야 해요. 열 게 없으면 버튼 모양을 빼요. "있어 보이려고" 넣은 가짜 탭 · 아이콘은 화면만 지저분하게 해요(쇼핑 홈 · 내 정보 탭).
- **늘 내용이 있게.** 데이터가 비어도 화면이 휑하면 안 돼요. 예: 지갑의 "지난 패스"는 다가올 패스가 없을 때 화면을 채우는 소품이라 늘 보여요. 빈 화면은 한 문장으로 무엇이 생기면 여기 모이는지 말해요.
- **지난 것은 회색으로.** 지난 패스 · 지난 일은 반투명이 아니라 회색조(`grayscale`)로 눌러요. 반투명은 뒤가 비쳐서 지저분해요.
- **빈 칸은 숨겨요.** 패스 · 영수증에서 값이 없는 칸은 라벨째 빼요.
- **제자리에서 먼저.** 목록에서 하나를 고르면 가능하면 같은 화면 안에서 펼치고(지갑 덱, 고정 지출 · 송금의 지난 내역), 한 번 더 누르면 상세로 가요. 고를 때 스크롤은 그대로 둬요.
- **같은 걸 두 번 보여주지 않아요.** 홈 맨 위에 고정 지출 카드를 넣었다가, 바로 내 계좌가 보이는 게 낫다는 말을 들었어요. 화면의 첫 자리에는 그 앱의 본론(계좌, 카드 덱, 오늘 날씨)이 와요.
- **그림 · 종류는 코드가 낱말로 골라요.** AI에게 고르게 하는 필드를 늘리지 않아요(5장).

#### 3-8. 움직임

- 움직임은 느리고 조용하게 해요. 구름은 오른쪽으로 아주 천천히 흐르고(초당 2~4px), 강풍만 빨라요. 안개는 움직이지 않아요. 별은 깜빡이고 해는 천천히 뜨고 져요.
- 숫자로 요청받은 속도는 정확히 그만큼만 바꿔요.
- `prefers-reduced-motion`이면 다 멈춰요.

#### 3-9. 고르는 법

- 시안은 서로 확실히 다른 방향으로 3~4개 그려요. 비슷한 시안 여러 개는 의미가 없어요.
- 소망이 하나를 고르고 일부를 바꿔 달라고 하면(예: "D가 예쁜데 지난 패스가 안 보여"), 고른 시안의 장점은 그대로 두고 그 부분만 풀어요.
- 실제 폰에 올린 뒤에도 몇 번씩 조금씩 다듬어요. 한 번에 완성하려 하지 말고, 바꾼 것만 짧게 말하고 화면을 보여줘요.

## 4. 놓치지 말 것

### 테마 충돌 (가장 많이 깨지는 곳)

소망은 SillyTavern **테마를 씌워서** 써요. 테마는 페이지의 모든 `button`, `label`, `input`, `select`에 배경 · 테두리 · 그림자 · 글꼴을 칠해요. 그래서 폰 안이 깨져요. 실제로 쇼핑 로고와 주문 탭이 소망 화면에서만 둥근 상자로 보였어요.

#### 규칙

1. **폰 안 `button` / `label`에는 `background`를 직접 쓰지 않아요. `--axbg`를 써요.** 그림자는 `--axsh`예요.
   ```css
   .ax .ax_myrow { --axbg: #fff; --axsh: 0 1px 2px …; }   /* background: #fff 는 안 먹어요 */
   ```
   `style.css`의 큰 규칙(아래)이 모든 폰 버튼 배경을 `var(--axbg, transparent) !important`로 덮어써요. `background:`를 써도 소용없어요.
   ```css
   body:is(.na_darkui, :not(.na_darkui)) dialog.popup:has(.na_popup) .na_popup .ax :is(button, label) {
     background: var(--axbg, transparent) !important; background-image: none;
     box-shadow: var(--axsh, none) !important; border-color: transparent !important; }
   ```
2. **배경을 꼭 칠해야 하는 버튼이 아닌 것**(div, span)은 `background`를 그냥 써도 돼요. 버튼처럼 눌려야 하지만 테마를 피하고 싶으면 `<div role="button" tabindex="0" data-go=…>`도 돼요.
3. 테마를 이겨야 하는 글자 크기 · 둥글기 · 테두리는 `!important`를 붙여요(예: `.ax_kp` 한국어 알약, 쇼핑 탭 밑줄). 같은 우선순위로 이기려면 위의 긴 선택자(`body:is(.na_darkui, :not(.na_darkui)) dialog.popup:has(.na_popup) .na_popup …`)를 앞에 붙여요.
4. **`input` / `select`**(은행 환율 칸 등)는 테마가 모양을 크게 바꿔요. 실제 입력칸은 투명(`opacity: 0`)하게 덮고, 보이는 값은 따로 그려요. 은행 `displayTools`가 이렇게 해요. 날짜칸은 누르면 `showPicker()`를 불러요(`phone.js`).
5. 글꼴은 `.ax_canvas`에서 `-apple-system, 'SF Pro Text', 'Noto Sans KR', sans-serif`로 정해요. 숫자는 `'Inter Tight'`, 숫자 칸에는 `.cg_num`을 써요.
6. 다크 UI: SillyTavern 쪽 패널은 `body.na_darkui`가 붙으면 어두운 팔레트예요(`src/theme.js`). 폰 화면 자체는 다크 테마를 따로 그리지 않아요. 어두운 테마에서도 폰은 같은 밝은 화면으로 보여야 해요. 확인은 `probe.cjs dark`로 해요.

#### 클래스 이름 충돌

- 클래스는 전부 전역이에요. 이름이 겹치면 엉뚱한 화면 규칙이 섞여요.
- 새 이름은 `grep -n "\.새이름\b" style.css src/*.js`로 비어 있는지 먼저 봐요. 앱 앞글자를 붙이는 게 안전해요(`lf_` 생활 앱, `dv_` 배달, `cd_` 카드 상세, `ax_bk…` 은행, `iv_` 투자, `cg_` 홈).

#### 홈은 다른 체계예요

- 잠금 · 홈 1쪽 · 2쪽은 `.na_ph_scr.cg`(`cg_gel` 컬러 젤 또는 `cg_mono` 화이트 그레이 테마 `p.theme === 'gray'`)이고 `.cg_canvas` 안에 그려요.
- 홈 아이콘은 `phonehome.js`의 `cgIcon`이에요. 색은 `CG_GEL[앱] = [밝은색, 진한색]`이고, 투명도는 `CG_ALPHA = 'd9'`예요.
- 날씨 위젯처럼 앱과 홈에 같이 쓰는 클래스는 `:is(.ax, .cg) .lf_city`처럼 둘 다에 걸어요.

### 함정

- **순환 import:** `phonehome.js`가 `phonelifeapps.js`를 import하면 "Cannot access 'AX' before initialization"이 나요. 홈 날씨 위젯은 `phone.js`가 만들어서 `homeScreen(p, now, m, 2, hereWidget(p, now))`로 넘겨요.
- **경로 값에 콜론:** `view.indexOf(':')`로 처음 콜론만 잘라요. 그래서 `data-i`에 콜론이 있어도 돼요.
- **테스트 스텁:** `tests/investment.test.mjs`는 `phonemoney.js`의 import를 손으로 이어 줘요. `phonemoney.js`에 새 import를 더하면 거기 맵에도 더해야 해요(예: `'./phoneprod.js'`).
- **은행 잔액:** `migrateBank(getMeta(), p)`가 장부(`finance.js`)에서 계좌 `balance`를 다시 써요. 테스트에서 `balance`를 직접 바꾸면 다음 화면에서 원래대로 돌아가요. 잔액을 바꾸려면 장부 `fin.finance(m).accounts["id:통화"].entries[id] = { amount, date }`에 넣어요.
- **폰 안에서 DOM을 자주 바꾸지 않아요.** 테마 방패의 `:has()` 규칙 때문에 스타일이나 속성을 한 번 바꿀 때마다 휴대폰 창 전체(요소 765개) 스타일을 다시 계산해요(느린 폰에서 한 번에 40ms, 그래서 지도 확대가 1초 넘게 굼떴어요). 손가락을 따라가는 건 화면의 canvas 하나에만 그리고 손을 뗄 때 한 번만 바꿔요(`phonemapzoom.js`: 지도가 뜨자마자 그림 한 장으로 떠 두고, 최근 지도 6장은 그대로 둬요). 그린 뒤에 재는 일은 읽기를 다 하고 쓰기를 모아서 해요(`notchPasses`).
- **CSS 괄호:** 한 줄에 규칙을 이어 쓰다 `}`를 빠뜨리면 그 아래가 전부 깨져요. 고친 뒤 `{` · `}` 수를 세 봐요.

### 데이터 쪽 경계 (반영 담당 세션)

- **반영 코드는 다른 세션(반영 쪽 오푸스) 담당이에요.** `src/phonesync.js`, `phonesyncmoney.js`, `phonesynclife.js`의 반영 부분, `src/phonedata.js`의 반영 지시문(약 199~213줄)이에요.
- 디자인 때문에 거기를 고쳐야 하면 직접 고치지 말고, 소망에게 **그쪽에 보낼 메시지**를 써 줘요. 무엇이 왜 필요한지, 지시문 토큰을 늘리지 않는 방법을 같이 적어요.
- 채우기(폰 처음 만들 때 한 번)와 반영(대화가 진행될 때마다, 지시문이 붐빔)은 달라요. 채우기에만 있는 것이 있어요(예: 지갑의 "지난 패스" 2~4개는 채우기에서만 지어내요).
- 날짜: 화면의 "오늘"은 `storyNow(p)`예요. 상태창(status tracker)의 날짜를 먼저 보고, 없으면 반영이 갱신하는 `p.now`를 써요.
- 화면은 이미 있는 필드만 읽는 게 원칙이에요. 낱말 추측은 화면 쪽 코드에서 해요.

## 5. 이렇게 하는 이유 (소망이 지적한 것 · 좋아한 것)

### 소망이 싫어하는 것 (실제로 지적받은 것)

- **그림자 없는 흰 덩어리.** 흰 카드 · 타일에는 그림자를 넣어요(3장 디자인 철칙 · 6장 공통 토큰).
- **누르는 척만 하는 버튼.** 보이는 버튼은 눌렀을 때 무언가 해야 해요. 할 게 없으면 빼요.
- **AI한테 고르게 하는 필드 늘리기.** 반영 지시문이 3500토큰이 넘고 고를 게 이미 많아요. 그림이나 종류는 **코드가 낱말로 추측해요**(who · memo · 한국어 ko 줄 포함, 영어 · 독일어 · 한국어 · 일본어 · 중국어). 새 필드가 꼭 필요하면 먼저 물어봐요.
- **은행처럼 생긴 화면, 답답한 화면.** 지갑 같은 앱이 은행 화면처럼 딱딱하거나, 빽빽해서 답답하면 안 돼요(지갑 시안에서 은행 같은 안 · 답답한 안이 빠졌어요).
- **보라는 조심해요.** 보라가 싫은 게 아니라, 화면에 넣는 순간 파스텔(유치함) 아니면 네온 시티펑크(게임 · 클럽 느낌)로 빠지기 쉬워요. 폰의 차분하고 깊은 톤과 안 맞아서 웬만하면 안 써요.
- 홈 아이콘은 비슷한 색끼리 붙으면 안 되고, **노랑이 똥색**이 되면 안 돼요. 하나만 채도가 튀어도 안 돼요(지갑 아이콘이 그랬어요).

### 소망이 좋아한 것

- 은행의 **남색 머리**와 둥근 버튼 **위쪽에 살짝 들어간 빛**(`box-shadow: inset 0 1px 0 rgba(255,255,255,.18)`)이에요. 예전 CSS가 더 고급스러워 보였던 게 이 빛 때문이었어요.
- 둥근 카드 아이콘이에요(`AX.card`, 지금 모든 앱 공통).
- 애플 지갑식 카드 덱이에요. 카드끼리 가장자리가 이어져 보이는 것, 뒤 카드를 누르면 그 자리에서 펼쳐지는 것도 좋아했어요.
- 플랫한 음식 그림, 홈 1쪽의 먼지 낀 파스텔 젤 아이콘이에요.
- 조금씩 자주 다듬어요. 예: 구름 속도를 "절반" → "10% 빠르게" × 2 → "5% 느리게" → "2.5% 느리게"로 맞췄어요. 숫자 요청은 정확히 그만큼만 바꿔요.

## 6. 화면별 참고

### 공통 토큰

- 흰 카드: `.ax_card`(`margin: 0 14px 12px; border-radius: 22px; box-shadow: 0 1px 2px rgba(22,27,34,.04), 0 8px 24px rgba(22,27,34,.05)`)예요. **새 흰 블록에는 이 그림자를 꼭 넣어요.**
- 위로 떠 있는 종이(명세서 · 확인증 · 거래 영수증): `0 1px 2px rgba(22,27,34,.05), 0 10px 26px rgba(22,27,34,.1)`
- 실물 카드 · 패스: `0 10px 24px rgba(22,27,34,.16~.18), inset 0 1px 0 rgba(255,255,255,.18)`
- 줄 목록: `.ax_rw`(왼쪽 아이콘 `.ax_fi`, 가운데 `.ax_tx` > `b.ax_n` + `.ax_p`, 오른쪽 `.ax_amt` 또는 `.ax_fxv`)
- 섹션 제목: `.ax_sec`(작은 회색), `.ax_shd`(굵은 + 오른쪽 개수)
- 배지: `.ax_dd`(빨강 기본, `.ok` 초록, `.g` 회색), `.ax_pend`(노랑 "대기"), `.ax_lnk`(파랑 연결)
- 칩: `.ax_chips > button`(`.on`은 남색). 남색 머리 위에서는 `.ax_mch`로 색을 뒤집어요.
- 확인 창: 폰 안에서 묻는 건 SillyTavern 팝업 대신 `phone.js`의 `askSheet(제목, 설명, 버튼, safe)`예요. iOS 액션 시트(`.pcf`, 시안 B · 질감 A)가 화면 아래에서 올라와요. 블러는 SillyTavern 설정에 따라 꺼지니 불투명 색 + 유리 테두리 + 두 겹 그림자로 띄워요. 회색 제목 · 한 줄 설명 + 빨간 버튼(`safe`면 남색), 따로 떨어진 "취소". 다시 그려져도 남아요(`placeAsk`). 제목은 짧은 질문, 설명은 한 줄, 버튼은 하는 일 이름(지우기 · 다시 만들기 …)이에요.

### 은행 (`.ax_bk`)

- 구조: `.ax_bkh`(남색 `#1d3461` 머리, 높은 건 `.ax_bkhs`, PRIVATE 더보기는 `.ax_bkpv` 검정) → `.ax_bks`(흰 시트가 머리 위로 28px 올라옴, 종이형은 `.ax_bkso`로 70px) → `.ax_scroll` → `tab('…')` 아래 탭
- 둥근 버튼 `.ax_bkc`(38px), 버튼 줄 `.ax_bkacts`(4칸, 계좌 화면은 `.ax_three`), 위쪽 빛 `inset 0 1px 0 rgba(255,255,255,.18)`
- 경로
  - `bank` 홈, `acct:i[.in|.out]` 계좌
  - `tx:id` 거래, `txdoc:id` 확인증(이체확인증 · 카드 매출전표 · 입금확인증, 도장)
  - `fixed[:a~key]` 고정 지출, `banksend[:a~key]` 송금, `stmt[:i.MM]` 명세서
  - `banknote` 알림, `bankmore` 더보기
- 고정 지출 찾기(`fixedCosts`)
  - `FIXED` 낱말 목록(월세 · 통신 · 영상 · 음악 · 보험 · 운동 · 공과금 · 구독 · 저축)
  - 낱말이 없으면 두 달에 걸쳐 같은 금액(3% 안)이 같은 날(±3일)에 나가고 송금이 아닐 때만 잡아요.
  - 처음엔 REWE 장보기가 잡혀서 이렇게 조였어요.
- 등급(`bankTier`)
  - 예금 합계를 유로로 환산해 정해요(`SCALE`). 4만 GOLD, 12만 PLATINUM, 40만 PRIVATE예요.
  - 은행 · 계좌 이름의 Gold, Platinum, Premium, Private, PB, Black 같은 말로도 정해져요.
  - 신용카드는 은행 등급 아래로 안 내려가요(`cardLook`의 `lv`).
  - 계좌번호(`acctNo`)는 나라 모양이에요(DE는 IBAN, KR은 3-3-6, JP · US · GB …). 은행 이름 + 끝 네 자리로 늘 같은 번호가 나와요.

- 반영 쪽이 넣는 돈 기록(자동이체 `tx.auto`, 잔액 조정 `tx.adjust`, 카드 대금 `tx.cardBill`, 정기 입출금 `regulars`, 자산 · 부채 `assets` · `debts`): 은행 글자는 은행 말로 써요(월 고정 지출 · 정기 입금 · 잔액 조정 …). "들어온 돈 · 나간 돈", "가진 것 · 빚" 같은 풀어 쓴 말은 말장난처럼 보여서 안 써요. 잔액 조정 이름은 은행 나라 말이고, 모델이 쓴 이유 `who`는 거래 상세의 "사유"에만 둬요(거래처 자리에 문장이 뜨면 안 돼요). "추정" 표시는 안 써요(진짜 은행엔 없어요). 배지를 이름 옆에 달면 줄이 바뀌어서 아랫줄에 붙여요. 자산 · 부채는 은행 더보기 안에만 있고(시안 `docs/mockups/phone-wealth` D), 첫 화면엔 자산 한 줄만, 부채는 안 보여요(빚을 첫 화면에 보여주는 은행은 없어요).

### 지갑 (`walletScreen(p, now, sel)`)

- 한 덱이에요. 순서는 PRIVATE 멤버 카드 → 카드들 → 다가올 패스(가장 가까운 게 맨 앞)예요.
- 펼쳐진 하나(`.ax_wlb.on`) 말고는 윗줄 60px만 보여요(`.sh`).
- 뒤 카드를 누르면 `wallet:키`로 그 자리에서 펼쳐져요(`m`, `c0`, `p<id>`, 지난 패스 `o<id>`). 펼쳐진 걸 누르면 상세로 가요.
- 펼친 카드 뒤쪽 카드들은 `.ax_dtail`에 담아요. 덱 끝 밑으로 삐져나오는 것만 잘려요. 카드 사이 가장자리는 **자르지 않아요**(소망이 이어지는 모습을 원해요). 다만 뒤에 깔린 카드는 윗줄 + 26px까지만 그려요(`.ax_wlb.sh > *` max-height). 앞 카드보다 긴 뒤 카드(기차 표 등)가 앞 카드 밑으로 삐져나와 보였어요. clip-path로 자르면 그림자가 옆에서 각지게 잘려요.
- 지난 패스는 아래에 회색 덱(`.ax_psold`)으로 따로 둬요. 다가올 패스가 없을 때 보이는 좋은 소품이라 늘 보여요.
- 카드 그림
  - `cardArt` / `cardLook`예요. 은행 색은 `BANK_C`(은행 이름 해시로 고름)예요. **목록에서 하나를 빼면 다른 은행 색이 전부 밀려요.** 빼지 말고 자리에 다른 색을 넣어요.
  - 무늬 `PATS`도 같아요. 사선 줄무늬는 빼고 그 자리에 물결을 넣었어요.
- 표가 끝났는지는 `PASS_OVER`(phonesyncmoney.js)로 봐요("미사용 · 환불 불가"는 안 끝남). 날짜를 모르는 표(`dayUnknown`)는 "날짜 미정", 날짜로 지난 표가 되지 않아요. 표 이름은 `by || to`. 숙박 · 회원권은 `until`까지(체크인 ~ 체크아웃, 회원권은 "까지 31.12."), 지난 건 `until`이 지나야. 캘린더는 표를 복사하지 않고 그때그때 읽어요(숙박은 날마다 점, 긴 회원권은 첫날 · 끝날 점 + 기간 동안 "오늘"에).
- 패스 그림은 `passArt`예요. 종류는 `passKind`가 낱말로 정해요(12종: 항공 · 기차 · 버스 · 배 · 숙소 · 콘서트 · 공연 · 영화 · 경기 · 전시 · 놀이공원 · 회원권, 그 밖은 티켓). **배치는 모든 표가 메인 지갑 그대로예요(표마다 · 모습마다 배치가 달라지면 안 돼요).** 색은 원래 지갑 색(`PASS`). 뒤 무늬는 `src/phonepassart.js`, 소망이 시안(`docs/mockups/phone-passes/`)에서 동그라미 친 것만 있어요. 종류마다 1~3개, 표 id 글자 합으로 골라요(이웃한 id끼리 번갈아요). 항공 둘째 · 기차 · 영화는 무늬 없는 모습(두 곳 사이에 비행기 · 기차 아이콘, 지구본 항공권은 아이콘 대신 가는 선). QR이 있는 상세 표에는 무늬가 없어요. 떼어 쓰는 표 양옆엔 반원 노치(`.ax_psnt`, 화면을 그린 뒤 `notchPasses`가 자리를 재서 `--ny`로 카드 바탕 · 무늬를 뚫어요, 그림자도 `drop-shadow`라 홈을 따라가요). 호텔 · 회원권은 표가 아니라서, 공연 · 영화는 무늬나 색이 이미 많아서 노치가 없어요. 무늬를 새로 그릴 때는 회원권 · 항공권과 같은 완성도로, 실제 모바일 티켓처럼 해요(3장 기준).

### 날씨

- 하늘
  - `scene(cond, phase)`이고, 날씨 10가지 × 새벽 · 낮 · 저녁 · 밤이에요(`pal()` 팔레트).
  - 시간대는 `phaseOf(time, sunrise, sunset)`예요.
  - 도시 카드는 `cardSky`, 홈 위젯은 `widgetSky`(340×150, 그림은 가운데)예요.
- 구름(`puffSvg(x, y, w, color, 초당px)`)
  - 전부 오른쪽으로만 흘러요. 나가면 왼쪽에서 다시 들어와요.
  - 속도는 소망이 맞춘 값이에요. 보통 2.24~3.9, 강풍 32~40. 바꿀 때는 요청한 비율만큼만 바꿔요.
- 안개: 움직이지 않아요. 위로 갈수록 얇고 흐린 줄 3개(오른쪽으로 비켜서)가 있고, 아래는 원래 안개 띠예요.
- 움직임은 `prefers-reduced-motion`이면 멈춰요.

## 7. 확장 패널 · 팝업 (휴대폰 바깥)

확장 자체의 화면도 같은 세션들이 시안을 거쳐 다시 그렸어요. 확장 목록 속 패널(홈 · 아카이브 · 압축 · 도구 · 설정 탭)과 거기서 여는 팝업(압축 작업실, 마법사, 섹션 둘러보기, 아카이브에 추가, 도감, 관계 온도, X-ray, 이야기 달력, 이동 경로, 섹션 연결망, 말투 지문, 망각 곡선, 세계관 공유 등)이에요. 휴대폰과는 분위기가 달라요. 휴대폰은 진짜 폰, 패널은 **크림색 종이 노트**예요.

### 7-1. 분위기

- **크림 · 갈색 · 주황**: 시안(목업)의 색을 그대로 써요. 밝은 테마는 크림 바탕에 갈색 글자, 강조는 탄 주황이에요. 다크는 차콜 바탕에 크림 버튼 · 금색 강조예요(3.168부터, 7-2 참고).
- **확장 자체의 테마**: 설정 › 테마에서 밝게 / 어둡게를 고르면 `body.na_darkui`가 붙어요(`src/theme.js`). SillyTavern 테마와 상관없이 패널 · 팝업은 이 둘 중 하나로만 보여요. 처음 한 번만 SillyTavern 글자색을 보고 밝은지 어두운지 골라요(`stIsDark`).
- **카드와 둥근 칩**: 내용은 둥근(14~16px) 카드(`--na-card`)에 담고, 고르기는 둥근 알약 칩 · 분할 탭(`.na_v2_tabs`, `.na_v2_seg`, `.na_v2_chips`)이에요. 선택된 탭은 종이색(`--na-paper`) 알약 + 주황 글자, 선택된 칩은 진한 갈색(`--na-fill`) + 크림 글자예요.
- **숫자는 고정폭**(`font-variant-numeric: tabular-nums`), 편집칸 · 원문은 SillyTavern 고정폭 글꼴(`--monoFontFamily`)이에요.
- **아이콘**: 새 화면은 선 아이콘 `svgA(ICO_A.이름)`(`src/theme.js`)을 써요. 예전 화면(홈 탭, 일부 버튼)에는 Font Awesome `<i class="fa-solid …">`이 남아 있어요.
- **홈 탭도 우리 팔레트예요**: 홈 탭(미터, 다음 할 일 카드, 빠른 버튼)도 나중에 시안(홈 7)대로 다시 그려져서 다른 탭과 같은 크림 · 차콜 팔레트예요. `css/41-home-theme.css`의 옛 "테마를 따라간다" 블록은 그 뒤 블록(`css/42-home.css`)에 덮여 있어요.

**규칙: 밝은 테마 규칙을 새로 쓰면 바로 뒤에 `body.na_darkui` 짝을 같이 써요.** 파일 전체가 이렇게 짝지어져 있어요(`/* dark themes: … Every light-only rule above has a body.na_darkui twin */`). 색은 직접 쓰지 말고 위 토큰을 쓰면 짝이 필요 없어요.

### 7-3. 테마 충돌 (패널 쪽)

SillyTavern 테마는 `.menu_button`, `input`, `select`, `textarea`, `small`, 체크박스, 팝업 바탕에 자기 색을 칠하고, 어떤 테마는 `!important`까지 써요. 패널은 이걸 이렇게 막아요.
- **팝업 바탕 · 글자 고정**: `dialog.popup:has(.na_popup, #na_settings)`에 바탕 `#F0E4DB` / `#2A221D`, 글자색을 `!important`로 박아요(`/* SillyTavern themes that force their own colours … */`).
- **SillyTavern 테마 변수 바꿔치기**: 패널 · 팝업 안에서는 `--SmartThemeBodyColor`, `--SmartThemeQuoteColor`, `--SmartThemeBlurTintColor` 등을 우리 팔레트 값으로 덮어써요. SillyTavern 자체 규칙이 이 변수를 읽어도 우리 색이 나와요.
- **버튼은 자기 클래스**: `.menu_button` 대신 `.na_btn`(`.na_primary`, `.na_small`)을 써요. 테마의 메뉴 버튼 규칙이 안 새요. 팝업 아래쪽 확인 · 취소(`.popup-controls .menu_button`)도 `!important`로 우리 색이에요.
- **스위치**: 체크박스는 숨기고(`skinToggles`, `input.na_toggle`) `.na_tgl_ui`가 스위치를 그려요. 테마 체크박스 CSS가 못 깨요.
- **입력칸**: 검색칸 · 연결 설정칸은 겉 상자가 칸을 그리고, 안의 `input`은 납작하게 둬요(`/* the input itself is bare; the wrapper draws the field */`). 테마 padding이 글자를 아이콘 밑으로 밀지 못해요. `.text_pole`은 크림 칸(`#F2E9E2`) / 짙은 칸(`#2E2621`)으로 고정이에요.
- **`<small>`**: SillyTavern의 `small { opacity: .7 }`이 새서, 패널 안 `small`은 `opacity: 1`에 우리 색이에요.
- **확장 목록 머리줄**: 기본 그라데이션 대신 패널 바탕색으로 칠해 패널과 한 덩어리로 보여요.
- **확인 창**(`util.confirm`, 이야기 고르기): 둥근 크림 카드에 그림자 두 겹, 큰 제목, "취소 · 실행" 알약 반반(실행은 주황 + 위쪽 빛)이에요. 지우는 창(`confirm(제목, 설명, 버튼, { danger: true })`)만 위에 주황 동그라미 아이콘 + 가운데 정렬, 나머지는 왼쪽 정렬이에요. 버튼은 하는 일 이름(지우기 · 바꾸기 …)이고, "아니요를 누르면 …" 창은 `{ no: 아니요 }`로 네 · 아니요예요. 고르기(라디오)가 있는 창은 왼쪽 정렬에 고르기가 알약(고른 쪽 진한 갈색)이에요(시안 `docs/mockups/ext-confirm` B). "이 이야기의 휴대폰"은 따로 질문 한 줄("같은 이야기인가요?") + 아이콘 타일 두 개(`.na_sc`, 시안 `ext-choice` B+C)예요. 기존 테마 방어 규칙에 id가 섞여 있어서(`:has(.na_popup, #na_settings)`) 이길 때는 `:not(#na_x)`를 붙여요. 팔레트 변수는 `.na_popup` 안에만 있어서 `dialog.popup:has(.na_confirm)`에도 걸어 뒀어요(버튼 줄이 `.na_popup` 바깥이에요).
- **아카이브에 추가**(`src/append.js`, `.na_ap3`, 시안 `docs/mockups/ext-append`): 위 카드에 큰 번호 + "초안 | 추가 후" 전환이 있고, 추가 후는 원래 미리보기(`.na_diff`, 손대지 않음)를 스크롤 상자에 보여줘요. "크게 보기"는 미리보기 · 고치기 칸 · 버튼 줄을 창 전체 화면으로 옮겼다가 돌아가기로 제자리에 돌려놔요(같은 요소를 옮겨요, 복사 아님). AI로 고치기는 작은 채팅이에요: 내 요청(주황) ↔ 답(초록 ✓ 고쳤어요 · 노랑 못 한 것 · 빨강 ✕ 못 고쳤어요). 답은 모델이 쓰지 않고 코드가 써요(바뀐 섹션 · 줄 수). 범위 칩은 번호 + 섹션 이름 한 줄. 아래 취소 · 추가하기는 창 안 버튼이고 팝업 자체 버튼은 숨겨요(`.na_ap3_dlg`).
- **빈 창 예시 인물**: 누가 아는가 · 대사 은행처럼 빈 창에 예시를 그릴 땐 이야기 속 사람 대신 Claude · GPT · Gemini를 써요. 얼굴은 `people.js`의 `exFace`로 그리고 색은 늘 고정이에요(Claude 주황 `#D97757`, GPT 차콜 `#3A3A3C`, Gemini 차분한 남색 `#3E5683`). 프사 없이 글자 동그라미예요.
- **창 크기 규칙(3.169.5):** 확장 창은 전부 내용만큼 뜨되, 최소 높이는 화면의 55%로 같아요(`style.css` 맨 끝 `window size`). 짧은 창도 너무 작지 않고, 큰 창으로 늘렸을 때처럼 텅 비지도 않아요. 길면 화면 끝까지 커지고 안에서 스크롤돼요. 확인 창 · 휴대폰 · 작업실 · 아카이브에 추가만 자기 크기를 써요. 버튼이 아래에 붙는 창(마법사, 이탈 감지 빈 화면)은 빈칸(`flex: 1`)이나 `margin-top: auto`로 내려요. 확인 사진은 폰 높이(412×870)로 찍어요. 너무 길게 찍으면 크기가 헷갈려요.
- **닫는 법은 하나(`src/popupchrome.js`):** 확장 팝업은 아래 "닫기"로만 닫아요. ✕나 "취소"를 닫기용으로 쓰지 않아요. 보기만 하는 창은 가운데 작은 "닫기" 하나, 무언가 하는 창은 "닫기(글자) · 하는 일(주황 알약)"이에요. 팝업이 열리면 이 파일이 자동으로 모양을 입히고 취소 버튼 글자를 "닫기"로 바꿔요. 확인 창(`util.confirm`)만 "취소 · 하는 일"이에요(취소가 대답이라서).
- 새 화면을 만들면 **아주 화려한 SillyTavern 테마**(버튼 · 입력칸을 `!important`로 칠하는 것)를 씌우고 한 번 확인해요. 소망 화면에서만 깨지는 일이 실제로 있었어요.

### 7-4. 코드 위치

| 파일 | 내용 |

- 팝업은 SillyTavern의 `callGenericPopup($root, POPUP_TYPE.TEXT, '', { wide: true, large: true, allowVerticalScrolling: true, leftAlign: true, … })`로 열고, 안쪽 루트에 `.na_popup`(새 화면은 `.na_v2`도)을 붙여요. 그래야 팔레트와 테마 방어가 걸려요.

### 7-5. 패널 디자인 원칙 (지금까지 굳은 것)

- 한 화면에 한 가지 일. 긴 설정은 묶음 카드(설정 탭의 목차 카드 B안)로 접고, 압축처럼 순서가 있는 건 마법사처럼 한 단계씩 보여줘요.
- 탭 머리는 큰 카드 하나에 "방법 고르기(분할 버튼) + 고른 방법의 한 줄 설명 + 큰 실행 버튼 하나"예요(압축 탭: 한 번에 · 작업실 · 마법사 → 압축하기).
- 기능을 더할 때 먼저 빼거나 합칠 걸 찾아요. 기능 정리(빼기 · 합치기)를 따로 한 적이 있어요.
- 결과 · 원문 · 차이는 고정폭 글꼴의 종이 같은 칸에 보여주고, 바뀐 부분만 색으로 짚어요.
- 이야기 도구(도감 · 관계 온도 · 달력 …)는 데이터가 그림이 되게 해요. 얼굴 동그라미, 온도 막대, 달력 칸, 연결망 점처럼요. 표만 늘어놓지 않아요.
- 패널 시안도 휴대폰과 같은 방식(서로 다른 시안 3~4개 → 고르기 → 실제 화면 확인)이에요. 밝게 · 어둡게 둘 다 찍어서 보여줘요(`probe.cjs light|dark`, 패널은 `#na_settings`나 `dialog.popup`을 찍어요).
